# Rule register

Every behavioural rule this repo implements: the section of [SPEC.md](SPEC.md) it comes from, where it lives in the code, and the test that proves it.

How to read this table:
- **Spec section** links to the heading in `docs/SPEC.md` that states the rule.
- **Design decision** marks a rule where there was a real choice and the repo took the stricter, fail-closed option. The bigger ones are explained in [DESIGN_NOTES.md](DESIGN_NOTES.md).
- **ASSUMPTION** marks a rule that rests on something outside this repo's control.
- `python scripts/check_rules.py` fails if any of these breaks:
  - a row's spec link doesn't point at a heading that exists in `docs/SPEC.md`
  - a row has no implementation or no test
  - a cited function or test doesn't exist
  - a cited test's docstring doesn't name the rule id

The rows are grouped by the part of the repo they live in: the mock API (`mock_api/`), then the client, payment gate, ledger and reconciliation, then the verdict verifier and the webhook receiver (all in `spend_guard/`), then the tools offered to a model (`mcp_server/` and `integrations/`).
